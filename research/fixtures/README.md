# Минимальные примеры официального тренажёра

Источник: https://digital.mchs.gov.ru/gims/simulator, наблюдения 2026-09-12 UTC через Playwright MCP и отдельный Python HTTP-клиент. Область и ограничения описаны в [протоколе](../../docs/mchs-testing-protocol.md).

| Файл | Происхождение и назначение |
| --- | --- |
| `simulator-form.html` | DOM-фрагмент формы до выбора марафона: все значения настроек. Удалены сгенерированные Select2 spans; CSRF заменён маркером |
| `marathon-initial.html` | DOM-фрагменты первого вопроса A: instance, counters, текст, картинка, форма и кнопка. Нормализированы отступы; instance заменён |
| `marathon-next-question.json` | Полный JSON после правильного ответа на № 1, содержит № 2. Изменены только instance UUID и представление JSON (отступы, Unicode) |
| `marathon-third-question.json` | Полный JSON после правильного ответа на № 2, содержит № 3. Те же преобразования |
| `protocol-exchanges.json` | Статусы, выбранные заголовки и тела запросов A; ссылки на тела ответов. Cookie, CSRF, activation/start/instance заменены. Тела редиректов не захвачены |
| `http-client-comparison.json` | Результат независимого марафона B: семь HTTP exchanges, metadata cookie без значения, UUID вариантов начального HTML, два полных JSON-ответа. Выполнено ровно два POST ответа |
| `client-protocol-excerpts.txt` | Дословные выбранные участки уже загруженных публичных bundles. Границы отмечены `[EXCERPT BOUNDARY]`; это материал анализа, не standalone JS |

`INSTANCE_A`, `INSTANCE_B`, `ACTIVATION_A/B`, `START_A/B`, `TEST_TEMPLATE`, `REDACTED_CSRF_TOKEN`, `REDACTED_COOKIE` — маркеры обезличивания, не реальные UUID/токены и не схема ID датасета. Реальные UUID вопросов/ответов и публичные URL изображений сохранены для проверки стабильности. Исполнять запросы из fixtures как готовые команды нельзя.

HTML — фрагменты живого DOM, а не полные byte-for-byte HTTP bodies. JS fragments сохраняют только относящуюся к публичному тренажёру логику; общие функции других подсистем и любые токены исключены. Бинарные изображения не сохранены. Реального multiple-примера в исследованной выборке не было.

Полезные будущие проверки парсера:

- Первый HTML: `1/1513`, четыре radio, корректное сопоставление UUID и текста правильного ответа, URL с портом 85.
- JSON № 2/3: question UUID, answer UUID, `single`, `is_additional=false`, пустые ресурсы ответов, counters и массивы ресурсов вопроса.
- `valid_answers` в JSON относится к возвращённому следующему вопросу. Начальный HTML `data-valid-*` нельзя повторно использовать после AJAX.
- Сравнение A/B: полное равенство JSON № 2/3 после замены только корневого `id`; совпадение UUID/порядка ответов первого HTML.

Эти fixtures не покрывают всю схему официальной базы и не заменяют отдельный реальный multiple-пример.
