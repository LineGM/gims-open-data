# gims-open-data — importer v0.1

Последовательная выгрузка официального марафона [МЧС России](https://digital.mchs.gov.ru/gims/simulator).
Контракт и происхождение примеров: [протокол](docs/mchs-testing-protocol.md),
[fixtures](research/fixtures/README.md).

## Установка (Windows PowerShell, Python 3.12)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Требуется именно Python 3.12.x (`>=3.12,<3.13`). Команды ниже запускайте из корня
репозитория. Активация venv не нужна; системный `python` может указывать на другую версию.

## Полная выгрузка — запуск вручную

```powershell
.\.venv\Scripts\python.exe -m gims_open_data.importer --all --delay 1.0
```

Импортирует все позиции, указанные сервером: исходно ожидается 1513. Если сервер
сообщает другое число при создании марафона, импортёр предупреждает и использует его.
Пауза не менее одной секунды после каждого запроса, включая redirects; параллельности
нет. Ориентир для 1513 позиций — от 25 минут плюс время HTTP и записи файлов.
Последний вопрос сохраняется без ответа на него: завершать тест на сервере для
получения корпуса не требуется.

Smoke (создаёт новый марафон и сохраняет максимум 10 вопросов):

```powershell
.\.venv\Scripts\python.exe -m gims_open_data.importer --limit 10 --delay 1.0
```

`--all` и `--limit` взаимоисключающие; один обязателен. `--delay` не может быть меньше
1.0. `--output PATH` меняет родительский каталог runs; для локальных данных оставьте
стандартный `data/runs`, который исключён из git.

## Результат

```text
data/runs/<UTC timestamp>/
  manifest.json
  raw/0001.html
  raw/0002.json ...
  normalized/questions.jsonl
  checkpoint.json
  summary.json
```

Raw сохраняется до нормализации, без повторной сериализации и перезаписи. Instance UUID
разрешён в локальном raw/checkpoint. Cookie, CSRF и activation/start secrets существуют
только в памяти: если их значения встречаются в теле ответа, они заменяются на
`REDACTED_SECRET` до записи. Manifest отмечает такое маскирование и содержит SHA-256
сохранённых raw-файлов. Заголовки, форма создания и тела redirects не сохраняются.
Для будущей публикации fixtures нужно создать отдельные sanitized-копии; локальный raw
для публикации не редактировать.

В normalized отсутствует instance. UUID первого вопроса остаётся `null` с
`id_status="unresolved_initial_html"`; `is_additional=null`, поскольку HTML его не сообщает.
`multiple` и `type` первого вопроса определяются по официальному HTML-флагу.
У следующих вопросов UUID/type/is_additional берутся из JSON. Только `valid_answers`
определяет правильность. Один UUID отправляется строкой, несколько — массивом.
Реальный multiple отмечается INFO; соответствующий raw уже сохранён.

Текст нормализуется в Unicode NFC, последовательности whitespace заменяются одним
пробелом. Fingerprint — SHA-256 канонического JSON из текста вопроса, упорядоченных
текстов ответов и URL их ресурсов. Порядок ответов и ресурсов значим; UUID, правильность,
позиция и дата получения не участвуют. Fingerprint не является официальным ID.
Исходные абсолютные URL ресурсов сохраняются со всеми портами/параметрами.

Каждая модель проверяет уникальность UUID вариантов, минимум два варианта, минимум один
правильный, принадлежность правильных UUID вариантам, согласованность correct и counters.
Single требует ровно один правильный; multiple — минимум два. Неизвестный type или
противоречие официальных полей останавливает импорт после сохранения raw.
На завершении повторно проверяется записанный JSONL: непрерывность позиций, reported
total, уникальность известных UUID, fingerprints. Дубли fingerprint отражаются в summary,
но сами по себе не считаются ошибкой. `complete` означает полноту сообщённого марафона.

## Остановка и checkpoint

После каждого записанного вопроса checkpoint заменяется атомарно. Перед POST записывается
`post_pending` с позицией отправляемого ответа. При timeout, 403, 429, 5xx или другой ошибке
импорт немедленно останавливается с ненулевым exit code. POST никогда не повторяется
автоматически. Повторяются только сетевые ошибки начального GET формы (до двух повторов
с backoff); activation/start GET не повторяются, поскольку тоже меняют состояние.

Успешный smoke имеет `status="limited"`; полный импорт — `complete`. После остановки
проверяйте `last_confirmed_position`, `pending_answer_position`, `status`, `error_kind`.
При аварийном завершении процесса статус может остаться `post_pending` — результат
такого POST неизвестен. Raw/JSONL иногда могут содержать запись после последнего
подтверждённого checkpoint: это не разрешение повторять POST.

**Автоматический resume в v0.1 отсутствует:** восстановление cookie-сессии и согласование
состояния сервера не подтверждены протоколом. Сохранять cookie запрещено. Для нового
импорта повторите команду: будет отдельный новый run, старые данные сохранятся.
Проверка корпуса не доказывает неизменность или полноту всей официальной базы за пределами
сообщённого сервером марафона.

## Offline-проверки

```powershell
.\.venv\Scripts\python.exe -m ruff check src tests
.\.venv\Scripts\python.exe -m ruff format --check src tests
.\.venv\Scripts\python.exe -m pytest -q
```

Обычный pytest запрещает сетевые подключения. HTTP-сценарии выполняются на MockTransport.
Multiple и варианты с несколькими ресурсами покрыты синтетическими тестами, отличными
от наблюдаемых fixtures. Отдельный type checker не настроен.

Проверка v0.1 выполнена 2026-09-12 на Python 3.12.3: 35 offline-тестов прошли,
ruff check/format прошли. Единственный live smoke (`--limit 10 --delay 1.0`)
сохранён в `data/runs/20260912T080438.227294Z`: 10/1513 позиций, 9 известных UUID,
1 unresolved, 10 single, 0 multiple, 10 с изображением вопроса, 0 с изображениями
ответов; дублей и ошибок нет. Проверены SHA-256 всех raw, равенство их повторного
разбора с JSONL, отсутствие instance в normalized и согласованность checkpoint.
Raw не потребовал маскирования. Реальный multiple в smoke не встретился.
Полный live import не запускался; проверка завершения покрыта offline-сценарием
с уменьшенным reported total.
